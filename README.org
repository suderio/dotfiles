* Bootstrap

** Configure git to manage the dotfile bare repo

Manage dot file with git, see https://www.atlassian.com/git/tutorials/dotfiles

Bootstraping can be done by the brave of heart with:
#+begin_src shell :tangle no
curl -fsSL https://raw.githubusercontent.com/suderio/dotfiles/refs/heads/main/install.sh -o dotfiles-install.sh
chmod +x dotfiles-install.sh
./dotfiles-install.sh
rm dotfiles-install.sh
#+end_src
The ~install.sh~ script is /literately/ made of the following code blocks in this page.
** Config in a new machine
*** Clone, don't show untracked files and checkout
#+begin_src shell :tangle install.sh
git clone --bare git@github.com:suderio/dotfiles "$HOME/.local/dotfiles"
git --git-dir="$HOME"/.local/dotfiles/ --work-tree="$HOME" config --local status.showUntrackedFiles no
git --git-dir="$HOME"/.local/dotfiles/ --work-tree="$HOME" checkout
#+end_src
*** Install mise and setup (this will take a long time)
#+begin_src shell :tangle install.sh
curl -fsSL https://mise.run -o install-mise.sh
chmod +x install-mise.sh
./install-mise.sh
rm install-mise.sh
mise up
#+end_src
*** Tasks
Mise tasks with all the tools, bells and whistles that can't be installed with mise tools.

#+begin_src shell :tangle install.sh
mise tasks ls
#+end_src

* Features & Architecture
This repository provides a unified workspace configuration aiming for high portability across various environments including:
- CachyOS Linux (bare metal)
- Ubuntu running via WSL2
- Windows (bare metal)
- RHEL 8/9 servers (unprivileged environments)
- Cygwin (via MobaXterm)

** Core Design Principles
- *Mise-centric Tooling:* Instead of heavily relying on native package managers exclusively, =mise= (mise.run) orchestrates the environment. Where root access or package manager access is absent, mise handles the installation of tools in user-space. Where available, OS packages can be defined in =config.<env>.toml=.
- *Theme Consistency:* The UI heavily favors the *Dracula* theme. This is standardized across terminal emulators (WezTerm, Alacritty), the multiplexer (Zellij), fuzzy finder (fzf), pagers (bat), the prompt (Starship), and editors (Neovim, Doom Emacs).
- *CLI/Emacs Focused:* Window manager configs are intentionally omitted or minimized. The workspace is built around efficient command-line use and Emacs.

** How-To / Setup
1. Clone the bare repo:
   #+begin_src shell
   git clone --bare git@github.com:suderio/dotfiles "$HOME/.local/dotfiles"
   git --git-dir="$HOME/.local/dotfiles/" --work-tree="$HOME" checkout
   #+end_src
2. Install =mise= securely:
   #+begin_src shell
   curl -fsSL https://mise.run -o install-mise.sh && chmod +x install-mise.sh && ./install-mise.sh && rm install-mise.sh
   #+end_src
3. Install tools:
   #+begin_src shell
   mise up
   #+end_src
4. (Optional) Run OS-specific task via Just (if available).


** Neovim Configuration
The Neovim setup (=.config/nvim=) is built on top of [[https://github.com/LazyVim/LazyVim][LazyVim]], providing a robust and fast configuration for development and sysadmin work.

*** Features
- *LazyVim Core*: Pre-configured with sensible defaults, lazy-loading plugins for fast startup.
- *Dracula Theme*: Consistent with the overall dotfiles setup, providing the Dracula colorscheme via =dracula.nvim= and integrated into LazyVim UI components.
- *Multi-language Support*: Ready for a variety of languages including Python, Node.js, Ruby, Rust, Go, C/C++, Java, Kotlin, Julia, Zig, Clojure, PHP, SQL, Markdown, YAML, TOML, JSON, and more via LazyVim's language extras (=lazyvim.json=).
- *Tools & Integrations*: Support for Docker, Git, Ansible, Helm, CMake, and a REST client.

*** Managing Dependencies
The Neovim environment requires various external dependencies (e.g., parsers, LSP servers, linters, runtime providers) to function fully across different languages:
- Most language toolchains (Python, Node.js, Ruby, Rust, etc.) and basic tools (ripgrep, fd, lazygit) are managed by =mise= through the environment-specific configs (e.g., =config.apt.toml=).
- *Providers Integration*: The =mise= configuration includes a =neovim= task (=mise run neovim=) to bootstrap Neovim provider packages for Python (=pynvim= via =uv=), Node (=neovim= npm package), Ruby (=neovim= gem), and Perl (=Neovim::Ext=). This ensures cross-environment consistency without depending on global OS packages.

** Gotchas & Limitations
- *MISE_ENV:* Detection of the package manager is purposefully decoupled from the global =.profile=. You must create a =.bashrc.d/00-mise-env= file defining =export MISE_ENV=apt= (or =arch=, etc.) based on your local machine to tell mise which configuration file to parse (e.g. =config.apt.toml=).
- *WSL2 Limits:* On WSL2 Ubuntu, certain tools (like eza) are not present in default apt repositories, so =mise= gracefully falls back to building/downloading them independently if removed from the =apt:= prefix.
- *Security:* Refrain from executing =curl | sh=. The repository enforces explicitly downloading and inspecting scripts before execution.
